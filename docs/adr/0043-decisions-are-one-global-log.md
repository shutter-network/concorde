# Decisions are one global log

A **Decision** is a Signed Statement the Decisions component numbered and kept: one global
append-only log, published by the agent, readable by any authenticated User, and addressed to
nobody. Four columns — `seq`, `statement`, `jws`, `created_at`.

## Naming the content is the product

Mechanically this is a log of signed strings that nothing interprets, so the generic instinct
says call it a Statement log and let one deployment mean "decision" by it and another mean
"receipt". **Here genericity destroys the product.** A signature over an uninterpreted
statement proves "this key signed some bytes", and a third party learns nothing they can act
on. A signature over a **Decision** means *this Shared Agent declared this to be a Decision*,
and that shared meaning is the whole of what a verifier is buying.

It is the same move [ADR-0034](./0034-the-http-messenger-is-an-opinionated-messenger.md) made
in the other direction: fixing the *content shape* is what created the generic client, and
fixing the content's *meaning* is what creates the generic verifier.

This is **not** a departure from
[ADR-0013](./0013-the-core-framework-stays-generic.md), and the temptation to write that it
is should be resisted. ADR-0013's scope is the **core** — Signals, dispatch, Session routing,
Run execution, the agent-facing API — and its mechanism is pushing concerns *out* of the core
into parts. This is a part, so it satisfies ADR-0013 rather than excepting it, exactly as the
thoroughly opinionated HTTP Messenger does.

**No qualifier**, unlike the HTTP Messenger's. ADR-0034 paid one up front for a peer messaging
Producer that may never exist, because message content genuinely varies by deployment. A peer
Decisions component with its own content shape would contradict the paragraph above: the value
is that the shape and the meaning are universal. Precedent considered and declined.

## Global, and invariant 2 does not hold here

No `user_id` column. `seq` numbers the one log, and every reader sees the same sequence.

A Decision addressed to one User would be a Message with extra steps, and worse: a verifier
holding a signed Decision could never tell whether the same Shared Agent had signed a
contradictory one for somebody else. **A commitment that is not public is not a commitment.**
Scoping one to a *set* of Users is unbuildable without reintroducing Party, which
[ADR-0008](./0008-party-is-not-in-the-data-model.md) keeps out of the data model.

So this is the framework's first deliberately **shared** surface, and invariant 2 of
[`data-model.md`](../data-model.md) — "no identifier or counter visible to a User is influenced
by another User's activity" — is re-scoped to per-User surfaces rather than restated. A global
`seq` is visible to everyone and moved by everyone's activity: a User reading the log sees that
Decisions 6 and 7 arrived and can infer from the timing that somebody else acted. That is not a
leak here, it is the function. Invariant 1's bar on Run and Signal provenance loses its stated
reason on this surface for the same reason.

**Reads require a Token all the same.** The Gateway is not the publication channel to the
world — a **User** is. They fetch a Decision and hand the artifact onward out of band, and the
signature is what lets it survive the hand-off. The Gateway serves no strangers, and `jwks.json`
is the one exception, being a public key.

## Not a Producer

Publishing writes a row and emits no Signal. A Decision is published *by the agent, during a
Run*, so emitting one would have the agent's own action queue work for the agent on a **serial**
worker ([ADR-0012](./0012-the-gateway-is-a-serial-signal-worker.md)) — the Signal queues behind
the Run still in flight, and the Handler it wakes can publish again. That is a loop with nothing
guarding it, and `architecture.md` already records that nothing here is bounded by time. This is
the User Manager's reasoning, which declines to emit a Signal per login for the same arithmetic.

**Consequence: nothing is notified when a Decision is published.** Users discover Decisions by
polling the log, exactly as they poll their Message log, or because the agent also sent them a
Message saying so — which a Handler holding both components does directly.

## The write path draws its number before signing

The JWS binds `seq`, so `seq` must be known before the signature exists. Inside one transaction:

```
seq = nextval(…)                                   -- atomic; no race, no retry, no lock
jws = sign({ seq, createdAt, statement })          -- via the Signatures component, in process
INSERT (seq, statement, jws, created_at)           -- jws NOT NULL
```

`seq` is `GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY`, and `BY DEFAULT` rather than `ALWAYS`
precisely because supplying the value by hand is what we do. `created_at` is generated in JS
rather than by `clock_timestamp()`, because the signed timestamp and the stored one must be the
same value and the only way to guarantee that is for one value to reach both. `messages`' reason
for `clock_timestamp()` is satisfied for free, each `publish` calling `new Date()` itself.

The considered alternative was to insert first, sign with the returned `seq`, then `UPDATE` the
row — correct inside one transaction, since a crash before `COMMIT` rolls back and no reader can
see an uncommitted row. It was rejected for costs that are permanent where the state it models
lasts microseconds: `jws` would be nullable in the schema and therefore optional in
`DecisionRecord` at every surface forever, and **PostgreSQL cannot enforce that it gets
filled** — `DEFERRABLE` applies to `UNIQUE`, `PRIMARY KEY`, `EXCLUDE` and `REFERENCES`, not to
`NOT NULL` or `CHECK`, so the only declarative guard is a deferred constraint trigger. Future
code that inserts and forgets the update would ship an unsigned Decision **silently**. Drawing
the number first keeps `jws NOT NULL`, keeps "no column is ever updated" literally true, and
costs the same two round trips.

**Gaplessness was not a goal, and an earlier draft was wrong to make it one.** A hole in the log
proves nothing either way, because the Operator is trusted and owns the database: they can
delete a row or renumber under any scheme. Detecting withheld Decisions needs a hash chain or a
transparency log, which ADR-0001 rejected. So a rolled-back transaction may burn a number, and
that is cosmetic.

## Four columns, and the seven that were considered

No `id` — a global `seq` is already unique, so a uuid is not a better cursor, not a better
handle, and saves no query. Rejected beyond that: **`run_id`** (it would be a second cross-schema
foreign key `drizzle-kit` cannot generate, repeating the hand-edit
[ADR-0036](./0036-the-http-messengers-user-id-is-a-foreign-key.md) calls the dangerous one; it
would be null for a Handler-published Decision and so mean two things; and Users cannot read Runs
at all, so it is inert to every reader who can see it); **`key_id`** (the cost is recorded in
ADR-0041 instead); **the public key on the row** (a key shipped inside the artifact it validates
proves nothing); **`published_by`** (it invites a verifier to weigh a claim the Gateway makes
about itself, and ADR-0001 collapses the distinction — both are the Operator's custody);
**`supersedes`** (the statement can say it, and nothing here interprets it); **`kind`/tags** (it
recreates the Signal `kind` registry ADR-0034 declined, on a surface with no dispatcher);
**`title`/`subject`** (two fields where one string does).

`jws` is `text` holding base64url, not `bytea`: it crosses the API in that form regardless, and
storing the encoded form is what keeps the stored bytes and the served bytes from disagreeing.
The column is `jws` and not `signature` because it holds a whole JWS, of which the signature is
one of three segments.

**Correlating a Decision to the Run that produced it is a manual timestamp join**, and two Runs
publishing inside one clock tick are ambiguous.

## Routes

| Server | Route | |
| --- | --- | --- |
| Agent | `POST /decisions` | 201, the `DecisionRecord`. `{ statement }`, `minLength: 1`, no `maxLength` — `bodyLimit` is the bound |
| Agent | `GET /decisions?after=&before=&limit=` | `{ decisions: [...] }`, ascending by `seq`. No Token |
| Agent, Public | `GET /decisions/:seq` | one Decision, so that citing one by number is a route rather than `?after=<n-1>&limit=1` |
| Public | `GET /decisions?after=&before=&limit=` | the same read, behind the User Manager's 401 |

The cursor, the capped limit, the envelope, the refusal of both cursors at once and the refusal of
an unknown query parameter are `src/route-conventions.ts`, unchanged
([ADR-0035](./0035-a-users-messages-are-one-log-read-by-cursor.md)). Trusted code gets
`publish(tx, statement)`, which takes the caller's transaction so that publishing a Decision and
recording in the Operator's own tables *why* cannot come apart
([ADR-0023](./0023-cross-component-writes-take-an-explicit-transaction.md)), and `history(options?)`.
No `userId` parameter anywhere.

**Two things are simpler here than in the HTTP Messenger**, and both follow from the log being
global. The agent's read and a User's read are the same query with no scoping at all — no `?user=`,
no Token-derived subject — so the two route groups differ only in whether an auth hook runs. And
**no route can 404 for a missing User**: with no `user_id` there is no foreign key, so ADR-0036's
"the agent's 404 is PostgreSQL's `23503` caught" has no analogue here, and Decisions imposes no
construction-order dependency on the User Manager.

## Consequences

- **A Decision is immutable and nothing removes one.** No delete, no TTL, no sweeper, no
  supersession field; a reversal is a new Decision whose statement says so. The table grows
  forever, as `messages` and `tokens` do.
- **The JWS is the Decision; the log is where Decisions are kept, not what makes them real.** A
  verifier holding a valid Decision cannot conclude a row exists, and does not need to — the
  signature is the authority (ADR-0042).
- **The agent can read the whole log**, which is the same read a User gets. A Session is a lossy
  cache, so an agent in a fresh Session has no memory of what it decided
  ([ADR-0011](./0011-the-agent-has-full-read-access.md)).
